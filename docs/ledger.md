### GAP-001 · 负向验证未执行

**事实**：`docs/changes/001-hello-world-baseline.md` §4 列了三条证伪用例，**一条都没跑**。
**风险**：D3 要求「判据必须可证伪」。未跑负向用例的判据，无法区分「正常」与「死代码」。
**解除条件**：重烧三次，分别注入三项故障并记录实际现象。
**阻塞**：否（不影响继续开发，但影响判据可信度）。

### GAP-002 · 03 环无独立测试

**事实**：现有全部验证（编译 / 烧录 / 串口 / 频率）**都由实现方自己执行**。
**依据**：`AGENTS.md` §4.2「实现方自写自验 ≠ 03 环准出」。
**解除条件**：派 `qa-validator` 产出独立测试方案；由 `falsifier` 做负向证伪；`gate-auditor` 裁决。
**阻塞**：是（03 环准出被阻）。

### GAP-003 · PSRAM 未启用

**事实**：`esptool flash_id` 报告 `Embedded PSRAM 8MB (AP_3v3)`，但 `sdkconfig` 无 `CONFIG_SPIRAM`。
**影响**：LVGL / 大缓冲区等场景可用内存受限（当前 DRAM 约 336 KiB）。
**解除条件**：需要大内存时加 `CONFIG_SPIRAM=y` 并重新验证。
**阻塞**：否。

### GAP-004 · 01 环无 ADR 与可测验收标准

**事实**：`docs/adr/` 为空；无 PRD；业务目标只有方向（"1.3 寸屏"、"遥控器"），无可测标准。
**依据**：`AGENTS.md` §2 门禁矩阵 01 环准出条件 = 「ADR 落盘 + Schema 迁移带时间戳 + 验收标准可测」。
**风险**：违反 D2 转段强阻断——在此状态下写业务代码属违规。
**解除条件**：用户提供业务需求（屏幕型号 / 显示内容 / 遥控器协议），由 `pm-spec-driver` 转成状态机 + 可测验收标准；
`system-architect` 出 ADR。
**阻塞**：是（阻断全部业务功能开发）。

### GAP-005 · 背光无法软件调光

**事实**：本板屏幕背光由 XL9555 的 `SLCD_PWR_IO`（数字 IO）控制，**只有开/关**。
`BSP` 中无任何 `ledc` 调用；`LCD_BL_IO` 虽在 `xl9555.h` 定义但未被使用。
**影响**：亮度无法运行时调节（用户反馈「太亮」后，只能改颜色值压暗）。
**定性**：**硬件限制，不修**。需真正调光要把背光改接到带 LEDC 的 GPIO。
**阻塞**：否。

### GAP-006 · 使用 IDF 已弃用的旧版 I2C 驱动

**事实**：启动日志告警 `This driver is an old driver, please migrate ... driver/i2c_master.h`。
**原因**：厂商 BSP（`components/BSP/IIC/iic.c`）基于旧版 `driver/i2c.h` 编写。
**影响**：当前功能正常；未来 IDF 大版本升级可能移除该驱动。
**解除条件**：把 `iic.c` 迁移到 `i2c_master.h` 新 API。
**阻塞**：否（当前 IDF v5.4.4 仍支持）。

### GAP-007 · BSP 为厂商代码副本，与上游无同步机制

**事实**：`components/BSP` 是官方 `12_spilcd` 例程的整目录复制，其中 `lcd.c` 有 2 处本地修改
（`SPI_LCD_TYPE` 与 `lcd_display_dir()`），已用 `/* ===== 本地修改（本项目） ===== */` 标注。
**影响**：厂商若更新 BSP，无法自动合并；两处本地修改在升级时会丢失。
**解除条件**：记录上游版本号（v5.1.2 例程 / 2023-08-26），升级时人工 diff。
**阻塞**：否。
